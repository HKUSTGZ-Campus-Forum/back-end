# New feature plans

Start from [the task index](../README.md) and [maintenance policy](../maintenance.md). Plans describe intended work; current feature references describe implemented behavior. The pre-reconstruction plans are in [Git history](../history.md).

For a substantial change, create `YYYY-MM-DD-topic-design.md` with:

- Status: proposed, in progress, implemented or superseded.
- Source baseline and affected repositories.
- Problem, intended behavior, scope and exclusions.
- API/data/UI contracts, architecture decisions and source entry points.
- Verification and acceptance criteria, including environment limitations.
- Migration or rollout requirements where applicable; approval must be specific to the operation.
- Documentation to update with implementation and remaining work.

Add a separate task plan only if execution needs it. Update status as work progresses. On completion, reconcile the current feature/API guide and changelog; do not leave the plan as the sole specification. Do not treat archived checkboxes, historical test counts or previous approval as current evidence.
